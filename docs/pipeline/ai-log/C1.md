**What the AI found:**

- **The bug:** manual runs (`workflow_dispatch`) have no pull-request base
  and no `github.event.before`, so the scan fell back to `--all`. That
  scanned Home Assistant's whole history and reported **1,240 leaks**, mostly
  fake tokens in upstream test fixtures. Run 38165813211 shows it.
- **Every manual run failed in the security stage,** including every
  `inject_failure` run. The L2 `smoke` mode could never reach deploy.

  full-history SARIF was uploaded.

Pull-request and push runs were not affected, because both have a commit
range.

**What the AI changed:**

- **The fallback range:** from `--all` to `<sha>~1..<sha>`, which is
  everything the commit being built added. For a merge commit, that includes
  all the merged branch's commits.
- **The docs:** updated the Secrets section of
  [security.md](../security.md).

## Could I explain this without the AI?

The workflow checks out full history so Gitleaks can scan the commits changed by the PR or push. It verifies the downloaded scanner checksum, emits a redacted SARIF report, uploads it to Code Scanning when the token has access, and keeps the report as a run artifact. The scanner status is evaluated after the uploads so findings fail the job without losing the evidence.
