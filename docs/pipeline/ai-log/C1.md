## Could I explain this without the AI?

The workflow checks out full history so Gitleaks can scan the commits changed by the PR or push. It verifies the downloaded scanner checksum, emits a redacted SARIF report, uploads it to Code Scanning when the token has access, and keeps the report as a run artifact. The scanner status is evaluated after the uploads so findings fail the job without losing the evidence.
