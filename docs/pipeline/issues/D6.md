## Why

Writing release notes is manual work that a model drafts well. A human still approves the final text.

## Tasks

- [ ] On a `v*` tag, collect the commit subjects since the previous tag. The commit subjects are untrusted data.
- [ ] Call `actions/ai-inference` and ask for markdown grouped as Features / Fixes / CI / Docs. Set `max-tokens`.
- [ ] Create the release as a **draft** with the generated notes. A human edits and publishes it.
- [ ] Save the AI draft and the published text, and compute the edit distance (for example with `difflib.SequenceMatcher` ratio) for the rubric.
- [ ] Upload `ai-release-notes.json`.

## Acceptance criteria

- [ ] The test tag produces a draft release with grouped notes.
- [ ] The published notes differ from the draft only where a human edited them.
- [ ] The edit ratio is recorded.
