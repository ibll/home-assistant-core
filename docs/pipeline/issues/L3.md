## Why

We have to *measure* whether the AI-assisted pipeline is effective and efficient (Q3), not just claim it.

## Tasks

- [ ] Create `.github/workflows/team-metrics.yml`: nightly schedule plus manual run, `actions: read` only.
- [ ] Use `gh api repos/{owner}/{repo}/actions/workflows/team-pipeline.yml/runs` and `.../runs/{id}/jobs` to compute: p50/p95 duration per stage, queue time, success rate, rerun count, and flaky count (from B4).
- [ ] Compute the DORA metrics from the deploy job runs: deployment frequency, lead time for changes (commit time → successful deploy), change-failure rate, and mean time to restore.
- [ ] Download the `ai-*.json` artifacts and sum tokens, latency and run count per AI job.
- [ ] Write `metrics.json` and a markdown summary to `$GITHUB_STEP_SUMMARY`.

## Acceptance criteria

- [ ] A nightly run produces `metrics.json` with every field above.
- [ ] The script handles zero runs without crashing.
- [ ] At least 2 weeks of data by the final report.

## Artifacts

`metrics-<date>` artifact containing `metrics.json` (retention 90 days).

## AI use

Optional: an AI-written weekly summary of the metrics. If you add one, it follows the AI job rules.
