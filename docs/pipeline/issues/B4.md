## Why

A flaky test that we silently rerun hides real bugs, and one we don't rerun blocks good PRs. We want both behaviors visible.

## Tasks

- [ ] On test failure, rerun once with `pytest --lf`.
- [ ] If the rerun passes, mark the run as "flaky": list the tests in the summary and in `flaky.json`, but still pass.
- [ ] If it fails again, fail the stage.

## Acceptance criteria

- [ ] A test made flaky on purpose (fails on the first run only) shows up in `flaky.json`.
- [ ] L3 reads the flaky count.
