## Why

The official image builds on `ghcr.io/home-assistant/amd64-homeassistant-base`, which is public, and installs every integration's requirements. We need to know early whether that fits in a GitHub-hosted runner.

## Tasks

- [ ] Build `Dockerfile` for amd64 with `--build-arg BUILD_FROM=ghcr.io/home-assistant/amd64-homeassistant-base:2026.07.0`. That version is `BASE_IMAGE_VERSION` in `builder.yml`; read it from there rather than hardcoding it.
- [ ] Record the build time, the image size, and any failures.
- [ ] If it fails or takes more than 40 minutes, write `Dockerfile.ci`: the same base, but install only `requirements.txt`, the package itself (`uv pip install -e .`), and `home-assistant-frontend` at the version in `homeassistant/package_constraints.txt`. D4's smoke test needs the frontend, because it serves `/manifest.json`. Document why.
- [ ] Use `docker/setup-buildx-action` and `docker/build-push-action` (pins in the README) with `push: false` for now, and cache with `cache-from/to: type=gha`.

## Acceptance criteria

- [ ] The decision (full image or `Dockerfile.ci`) is written down with its numbers.
- [ ] The build succeeds in `team-package.yml`.
