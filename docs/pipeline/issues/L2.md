## Why

Checklist Q14 asks whether the pipeline fails *correctly*. We prove it by forcing each stage to fail and checking that everything after it stops.

## Tasks

- [ ] For each value of `inject_failure` (`lint`, `test`, `security`, `smoke`), run `gh workflow run team-pipeline.yml --ref main -f inject_failure=<value>`.
- [ ] For each run, record which stage failed, which stages were skipped, and whether anything was deployed.
- [ ] Repeat at the end of week 3, once the real stages exist.
- [ ] Add a real-world case too: a PR that breaks a test on purpose (not via injection) must fail in the test stage.

## Acceptance criteria

- [ ] A table in `docs/pipeline/failure-injection.md` with one row per mode: expected result, actual result, run link.
- [ ] In every mode, the injected stage fails and package/deploy are skipped (or rolled back, for `smoke`).
