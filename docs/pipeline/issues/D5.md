## Why

A pipeline that can deploy must be able to undo a bad deploy without a human. A Release ties all our artifacts to a version.

## Tasks

- [ ] After a successful smoke test, retag the digest as `:staging`.
- [ ] If the smoke test fails, keep `:staging` on the previous good digest (or retag it back), print which digest is live, and fail the job.
- [ ] On a `v*` tag push, create a GitHub Release with the wheel, `SHA256SUMS`, both SBOMs and the image digest attached. This needs `contents: write` on that job only.

## Acceptance criteria

- [ ] An `inject_failure=smoke` run leaves `:staging` on the previous digest. Show it with `docker buildx imagetools inspect`.
- [ ] A test tag `v0.0.1-team` produces a release with every artifact attached.
