## Why

Issues are disabled on the fork, so we can't track work yet. Deploy needs a human approval gate, and `dev` needs required checks so a red pipeline actually blocks merging.

## Tasks

- [ ] Settings → General → Features: enable **Issues**.
- [ ] Settings → Environments: create `staging`. Add the tech lead as a required reviewer and restrict it to the `dev` branch.
- [ ] Settings → Branches: protect `dev`. Require a PR, 1 approving review, and the `team-pipeline` status checks for build, test and security. Do **not** require the AI advisory job.
- [ ] Settings → Actions → General: set workflow permissions to read-only by default.
- [ ] Settings → Packages: confirm GHCR is allowed for the repo.
- [ ] Add an "AI used" section to `.github/PULL_REQUEST_TEMPLATE.md`, asking for a link to the AI-log entry. Add only; never remove anything from the template.

## Acceptance criteria

- [ ] Screenshots of each settings page are in `docs/pipeline/setup.md`.
- [ ] A test PR with a failing required check cannot be merged.
- [ ] A deploy run waits for approval.
