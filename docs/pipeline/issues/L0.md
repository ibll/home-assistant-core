## Why

Every member needs a file of their own to work in, plus one place that wires the stages together. Without this, four people edit the same workflow at the same time and conflict.

## Tasks

- [ ] Create `.github/workflows/team-pipeline.yml` (triggers: pull request, push to `dev`, manual run). Set `permissions: {}`, `concurrency`, and a fork guard (`github.repository == 'ibll/home-assistant-core'`).
- [ ] Create one reusable stub per stage: `team-{changes,build,test,security,ai-advisory,package,deploy}.yml`.
- [ ] Add the `inject_failure` input and the `./.github/actions/team-inject-failure` composite action.
- [ ] Write `docs/pipeline/README.md` and `docs/pipeline/ai-log/TEMPLATE.md`.

## Acceptance criteria

- [ ] zizmor `--pedantic`, actionlint and yamllint report zero findings on `team-*`.
- [ ] A run of `team-pipeline` on a branch is green, with every stage stub shown.
- [ ] No upstream workflow file is modified.
